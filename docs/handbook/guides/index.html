Start with one request.

Then follow the city, the code and the decisions. Every stop has something to explain back in your own words.

  1. Picture the whole system

    Read the architecture and follow one search, login and booking. Separate synchronous decisions from background effects.

    Self-check: which store can confirm the last seat, and which counters are only hints?

  2. Walk through the city

    Start with build order, then booking, database reach, IAM badges and a failing email. Open the console/code/CLI boxes one step at a time.

    Written build-along, 25 chapters · How a release reaches AWS

    Self-check: prove Reach, Allowed and Password independently.

  3. Read the source

    Search for outbox, idempotency, CSP and keyset pagination. Snippets are generated from the committed source anchors; open the full file and follow its numbered comments.

    Self-check: name the component, hook, procedure, service and query involved.

  4. Defend the decision

    Filter the 55 scenarios by area or implementation status. Read the short answer, trace the mechanism and compare the alternatives and 10x/100x changes.

    Full written scenario guide · All concept cards

    Self-check: identify which features are explain-only and exactly where they would go.

  5. Rehearse without the answer

    Use flashcards and quizzes per area. Say a 30-second answer, then handle the counter-question. Progress stays in this browser.

    Self-check: distinguish locally tested code from live AWS acceptance.
